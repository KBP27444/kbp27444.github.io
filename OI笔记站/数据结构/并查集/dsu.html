并查集 (Disjoint Set Union) ​

1. 什么是并查集？ ​

并查集是一种用于处理一些不交集的合并及查询的数据结构。顾名思义，不交集的意思是一个元素只能在一个集合当中。

应用场景 ​

  • 连通性问题（如图的连通块）
  • Kruskal 最小生成树算法
  • Tarjan 离线算法求最近公共祖先（LCA）

2. 核心操作 ​

在并查集中，我们给每个不交集一个代表元素，也就是这个集合的"大哥"。

可以把并查集的合并想象成"帮派认大哥"的过程：

  1. Find（查找）：确定元素属于哪一个子集。也就是"找这个人的最高级大哥是谁"。
  2. Union（合并）：将两个子集合并成同一个集合。也就是"让一个帮派的大哥去给另一个帮派的大哥当小弟"。

判断两个元素是否在同一个集合，只需判断这两个元素的最高级大哥是否相同即可。

3. 基础实现：朴素并查集 ​

在数组中，我们用 fa[i] 来记录元素 i 的"上级（父亲）"。初始时，每个人都是自己的大哥：fa[i] = i。

cpp
int fa[MAXN];

void init(int n) {
    for (int i = 1; i <= n; i++) fa[i] = i;
}

int find(int x) {
    if (fa[x] == x) return x;
    return find(fa[x]);
}

void merge(int x, int y) {
    int fx = find(x), fy = find(y);
    if (fx != fy) fa[fx] = fy;
}

4. 时间复杂度优化 ​

如果形成一条链（比如 1 -> 2 -> 3 -> 4），find 可能会退化为 O(N)。

优化一：路径压缩 (Path Compression) ​

核心思想：既然我们只关心"最高级大哥"是谁，不关心中间的层级关系，那为什么不在 find 的时候，顺便把路径上的所有人直接连到最高级大哥下面呢？

cpp
int find(int x) {
    if (fa[x] == x) return x;
    return fa[x] = find(fa[x]);
}
  • 优点：代码极短，只需加几个字符。后续查询时间直接降为 O(1) 级别。
  • 缺点：破坏了树的原本结构（在某些高级应用如可持久化或撤销操作中不可用）。

优化二：按高度（秩）合并 (Union by Rank) ​

核心思想：为了防止树退化成链，合并时我们总是把矮的树连到高的树下面。这样合并后的树高度最多只会增加 1（当且仅当两棵树一样高时）。

cpp
int fa[MAXN], dep[MAXN];

void merge(int x, int y) {
    int fx = find(x), fy = find(y);
    if (fx != fy) {
        if (dep[fx] < dep[fy]) {
            fa[fx] = fy;
        } else if (dep[fx] > dep[fy]) {
            fa[fy] = fx;
        } else {
            fa[fx] = fy;
            dep[fy]++;
        }
    }
}

实际操作时，也可以不采用树的高度，而采用树的大小，这样维护起来更方便。可以证明，两者的复杂度是等价的。

cpp
int fa[MAXN], sz[MAXN];

void merge(int x, int y) {
    int fx = find(x), fy = find(y);
    if (fx != fy) {
        if (sz[fx] > sz[fy]) swap(fx, fy);
        fa[fx] = fy;
        sz[fy] += sz[fx];
    }
}

结合路径压缩与按秩合并，单次 find 时间复杂度为 O(α(N))（反阿克曼函数），这个函数在实际情况下是近乎完美的常数级别 O(1)！

5. 进阶：可撤销并查集 (Undo Union-Find) ​

什么是"可撤销"？

有时候题目不仅要求我们执行合并和查询，还要求回到上一次操作之后的状态。

实现思路：只需要记录每次操作时变化的值即可。具体的说，假如 x 的父亲被修改成了 y，那我们只需要把 x 记录下来，撤销的时候把 x 的父亲修改回 x 即可。

⚠️ 可撤销并查集的致命大坑 ​

绝对不能使用路径压缩！

为什么？

  1. 路径压缩在单次 find 时可能会修改大量节点的 fa 值。
  2. 如果我们记录所有这些点的 fa 被修改，那只需要反复执行再撤销一次，修改大量节点的 fa 值就会超时。

正确的做法：在可持久化并查集中，必须且只能使用"按秩合并"。

按秩合并可以保证树的最大深度始终不超过 O(log N)，这样每次 find 时找根节点的跳跃次数必定是 O(log N)。

cpp
vector<int> dt;

void merge(int x, int y) {
    int fx = find(x), fy = find(y);
    if (fx != fy) {
        if (sz[fx] > sz[fy]) swap(fx, fy);
        dt.push_back(x);
        fa[fx] = fy;
        sz[fy] += sz[fx];
    }
}

void ctrlz(int t) {
    while (dt.size() > t) {
        int x = dt.back();
        dt.pop_back();
        sz[fa[x]] -= sz[x];
        fa[x] = x;
    }
}

6. 应用：种类并查集 ​

问题描述 ​

现在有 n 个人，他们之间有可能两种关系：朋友和敌人。当然，他们可能没见过面，所以没有直接关系。我们只知道：

  • 一个人的朋友的朋友是朋友
  • 一个人的敌人的敌人是朋友

现在要对这些人进行组团。如果两个人是朋友，那么这两个人一定在同一个团体中，并且一个人只能加入一个团体。请求出这些人中最多可能有的团体数。

解法 ​

对每个人 i 建两个并查集节点：

  • 集合 i 表示 i 的朋友所在的集合

  • 集合 i + n 表示 i 的敌人所在的集合

  • 如果 x, y 是朋友 → 合并 x, y

  • 如果 x, y 是敌人 → 合并 x + n, y 以及 x, y + n

为什么 x, y 是朋友不需要合并 x + n, y + n？因为题目没说"朋友的敌人是敌人"。

7. 应用：带权并查集 ​

种类并查集是关系并查集的一种简化版。当关系较为复杂时，我们采用权值记录信息，计算关系。

问题描述（NOI2002 银河英雄传说） ​

有 30000 个战舰，第 i 个战舰的编号为 i，初始时每个战舰占据一列。

  1. M i j：把 i 号战舰所在的那一列作为一个整体（头在前尾在后）接至 j 号战舰所在的战舰队列的尾部。保证 i, j 不在同一列。
  2. C i j：如果 i 号战舰和 j 号战舰在同一列输出 -1，否则求两者之间的战舰数量。

解法 ​

记录每个战舰到这个战舰所在列的第一个战舰的距离 sum[i]，同时记录第 i 个战舰所在的那一列的战舰数量 sz[i]。

如果询问 i, j 之间的距离，答案是 |sum[i] - sum[j]| - 1。

cpp
int find(int x) {
    if (fa[x] == x) return x;
    int fx = find(fa[x]);
    sum[x] += sum[fa[x]];
    return fa[x] = fx;
}

void merge(int x, int y) {
    int fx = find(x), fy = find(y);
    fa[fx] = fy;
    sum[fx] += sz[fy];
    sz[fy] += sz[fx];
}
