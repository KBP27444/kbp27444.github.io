安装与常见问题

❓ 安装与常见问题 ​

←返回工具详情

Q1：点击扩展图标没反应？ ​

  • 检查 VSCode 右下角是否有「OJ服务器已启动」通知。
  • 如果没有，重启 VSCode。
  • 仍不行？在 VSCode 中按 Ctrl+Shift+P → 输入 OJ，查看扩展命令是否正常。

Q2：提示端口 8765 被占用？ ​

说明你开了多个 VSCode 窗口。关掉多余的窗口，只留一个即可（多窗口时只有第一个能启动服务器，不影响使用）。

Q3：支持其他 OJ 吗？ ​

目前只适配了 实验舱 OJ。其他 OJ 平台的 API 结构和字段名不同，需要修改代码才能支持。

Q4：Edge 重启后第一次点击没反应？ ​

浏览器会话重启后缓存会被清空。刷新一次题目页面再点图标即可。

Q5：文件创建失败？ ​

  • 检查题目名称是否包含 Windows 不允许的字符：\ / : * ? " < > |。
  • 检查 VSCode 是否已打开工作区文件夹。
  • 检查磁盘是否有写入权限。

Q6：数据会上传到云端吗？ ​

不会。所有数据都在你的电脑本地流转：

OJ 页面 → Edge 扩展 → 本地 WebSocket → VSCode 扩展 → 本地文件

WebSocket 服务器绑定在 127.0.0.1，仅本机可访问。

Q7：VSCode 每次都要按 F5 启动吗？ ​

不需要。安装 .vsix 后，每次打开 VSCode 会自动激活扩展并启动服务器，无需手动启动。

Q8：Edge 提示「此扩展程序可能不安全」怎么办？ ​

因为扩展没有上架 Edge 商店、未经官方签名，属于正常提示。点击「保留」或「仍要启用」即可继续使用。

🐛 反馈与建议 ​

如果遇到问题或有功能建议，欢迎通过 GitHub Issues 反馈： https://github.com/KBP27444/kbp27444.github.io/issues

反馈时请附上：

  • 操作系统版本
  • Edge / VSCode 版本
  • 问题现象截图
  • VSCode 扩展 Service Worker 控制台日志（在 edge://extensions/ 页面点击扩展的「Service Worker」链接）
